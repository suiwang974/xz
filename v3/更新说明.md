# SniffDL 更新说明 · 网盘直链 / 外部推送（2026-11-06）

扩展版本：**0.6.0**（原 0.5.14）　主程序：源码已改，**exe 需在 Windows 上重新打包**。

一句话：**油猴网盘脚本（LinkSwift / 网盘直链下载助手）推送到 SniffDL 显示「分发成功」却没下** 的问题已修好，默认配置下不用改任何设置就能用；用法照旧——**贴链接 → 自动识别 → 开下**。

---

## 一、这次改了什么

1. **开箱即用的默认值**：本地下载服务（RPC）默认 `127.0.0.1:6800`、**不设 token**，和 aria2 / 网盘脚本的默认一致。
   旧版测试期留下的 `6820 + tk-test` 会在**第一次启动时自动改回 6800 / 空**（日志里有一行 `[配置迁移]`），其它设置（下载目录、画质、桌宠、大脑网关……）一律不动。浏览器扩展里存的旧值也会一起改回。
2. **网盘规则表**（新文件 `netdisk_rules.py`）：夸克、UC、百度、阿里云盘、123、迅雷、蓝奏、115、天翼 每家一行规则——用几条连接、缺 Referer/UA 时补什么、Cookie 去哪个域取、签名直链几点过期。出处见 `docs/netdisk_rules.md`。
3. **请求头原样使用**：脚本 / 浏览器给的 UA、Cookie、Referer 一字不改，只在缺的时候补默认值。
4. **失败原因看得见**：缺 Cookie、链接过期、UA 不对、限流……直接用中文写在任务列表那一行里（红字），不再静默失败。
5. **浏览器扩展 0.6.0**：网盘下载一律接管，并带上浏览器真实发出的请求头（含 httpOnly Cookie）；把网盘登录 Cookie 同步给桌面端（只放内存、不落盘），所以手动粘贴网盘直链也能下。
6. **粘贴网盘直链直接下**：主界面贴网盘直链 → 自动识别成直链下载（不走嗅探）；不是网盘的链接照常嗅探。
7. **界面不加新按钮**：「推送地址 / token / 自定义请求头」都收进 设置 → **「高级 · 网盘直链 / 外部推送」** 卡片（默认折叠，点开才显示）。主界面去掉了上一版临时加的「请求头」按钮。
   - 推送地址旁有「复制」按钮；显示的是**实际在监听的端口**。
   - 自定义请求头一般不用填；填了只作用于**下一条**粘贴的链接，用完自动清空。
8. **确认窗**：用户主动发起的下载会弹「下载文件信息」窗，现在 Web 界面模式下一定看得见；按 **回车 = 开始下载，Esc = 取消**。
9. **本机地址不走代理**：电脑上设了 HTTP(S)_PROXY 环境变量时，以前连 127.0.0.1 也会被发给代理，导致莫名 404；现在本机回环地址永远直连。

## 二、「分发成功但没下」的 6 个根因（都已修，并有自动化测试盯着）

| # | 根因 | 以前的表现 | 现在 |
|---|---|---|---|
| 1 | 同一文件已有「待继续 / 稍后」旧任务（重启后记忆系统恢复出来的）时，新推送被当成「重复提交」吞掉，只回旧任务编号 | 脚本显示成功，SniffDL 里那条一直不动 | 旧任务没在跑 → 用这次推来的新链接 + 新请求头把它复活并立刻开下；真在跑才算重复 |
| 2 | 直链借用 BT 守护进程的队列（最多同时 5 个），被种子/别的任务占满后新推送一直排队 | 永远「排队」 | 直链走独立的多连接引擎，不和 BT 抢队列 |
| 3 | 端口对不上：6800 被别的 aria2 / Motrix 占了时悄悄换到 6801…；加上旧配置是 6820 + token「tk-test」，而脚本默认推 6800、不带 token | 任务推给了别的程序，或鉴权失败 | 默认 6800 / 无 token + 旧配置自动迁移；被占用时日志大声提示；设置里显示实际推送地址 |
| 4 | Web 界面模式（默认）下 Tk 主窗是隐藏的，确认窗挂在主窗上（transient）跟着一起被隐藏 | 返回「pending」后再也没下文，用户根本看不到「开始下载」按钮 | 主窗隐藏时不挂 transient（窗口仍置顶），确认窗一定弹出来；另加回车/Esc 快捷键 |
| 5 | 推送方的请求头被覆盖或没被认出：程序自带的 Chrome UA 顶掉脚本给的 UA；只放在 aria2 `user-agent` 选项里的 UA 不认；小写 `user-agent` 头变成两个 UA | 百度 / 115 这类绑定 UA 的直链必 403 | 大小写不敏感合并、推送方优先，`header` 和 `user-agent`/`referer` 选项都认 |
| 6 | 失败静默：412（缺 Cookie）、403、链接过期 只在内部日志里，任务列表看不出原因；脚本传 `dir=D:` 这种裸盘符时被当成保存目录 | 「失败」但不知道为什么 / 文件落到奇怪的地方 | 中文原因写进任务行；过期链接提前识别；裸盘符不当目录，落到 SniffDL 下载目录 |

## 三、怎么让网盘脚本推到 SniffDL（LinkSwift / 网盘直链下载助手）

1. 先启动 SniffDL（默认就开着本地下载服务，不用设置）。
2. 在网盘页面打开脚本的设置（LinkSwift：下载弹窗里点「修改服务参数」/ 设置）：
   - 推送方式 / 下载器：选 **aria2 / Motrix（RPC）**
   - RPC 地址：**`http://127.0.0.1:6800/jsonrpc`**（也可以填 域名 `http://127.0.0.1`、端口 `6800`、路径 `/jsonrpc`）
   - 密钥 / token：**留空**
   - 保存目录：留空即可（SniffDL 会按文件类型放进自己的下载目录）
3. 点脚本的「测试连接」应该显示成功；然后选文件 → 「发送到 Aria2 / RPC 下载」，SniffDL 里马上出现任务。
4. 如果以前给 Motrix 配过，端口多半是 **16800**，要改成 **6800**。如果 SniffDL 日志提示 6800 被占用、改用了别的端口，以设置页「高级 · 网盘直链 / 外部推送」里显示的推送地址为准（可一键复制）。
5. 下载失败时看任务行的红字原因：多数是「缺登录 Cookie」（网盘网页没登录 / 扩展没装）或「链接已过期」（回网盘重新点下载）。

## 四、浏览器扩展要重新加载

扩展升级到 0.6.0 后，打开 `chrome://extensions` → 找到「SniffDL 下载接管」→ 点 **刷新（重新加载）** 按钮；
新装的话：右上角开「开发者模式」→「加载已解压的扩展程序」→ 选 `extension` 文件夹。
（0.6.0 没有新增权限，原有的 webRequest / cookies 权限就够用。改过扩展一定要点刷新，否则还是旧版在跑。）
